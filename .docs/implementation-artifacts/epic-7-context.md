# Epic 7 Context: Lecturer overview, Game insight and Messages

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

A Lecturer or Assistant lecturer can follow every Class game of a Class session live on the Oversikt, open any Game week by week in Spillinnsikt, and send one-way Messages that reach Students in the product and by email. The epic owns the staff side of `backend/app/modules/games/` and `frontend/src/modules/games/`, all of `backend/app/modules/messaging/` with `frontend/src/modules/messaging/`, adds the Matrisevegg and staff charts to the shared `frontend/src/components/charts`, and adds wall aggregates to the shared `analysis/`. Pause, Takeover and other Spillstyring actions belong to Epic 8; here the Varselbånd shows only the longest-waiting Class game with «Send Melding».

## Stories

- Story 7.1: See the status of every Class game on the Oversikt
- Story 7.2: Read all Class games week by week on the Matrisevegg
- Story 7.3: Switch the wall to «Vis som tabell»
- Story 7.4: Filter the wall and compare with the class median
- Story 7.5: Follow the games live with «Oppdater automatisk»
- Story 7.6: See who waits, the class's cost and the funnel in the right rail
- Story 7.7: Open one Game week by week in Spillinnsikt
- Story 7.8: See all four Roles' Orders, inventory and backlog as charts in Spillinnsikt
- Story 7.9: Send a Message to a Student, a Class game or the whole Class session
- Story 7.10: Read Messages in the product
- Story 7.11: Act on the longest-waiting game from the Varselbånd

## Requirements & Constraints

- Staff (Lecturer and Assistant lecturer of the Class) see every Class game's status, current Week, whom it waits for and for how long, occupants and running chain Total cost; headline counts read like «41 ferdig · 15 pågår · 4 venter». Students, staff of other Classes and unattached Admins are refused, with an answer identical whether or not the Class session exists.
- Game status has one definition: `games.rules.game_status(game, turns)` returning `not_started`, `running`, `waiting`, `finished` (Epic 8 adds `paused`). `waiting` = at least one Student ordered in the open Week and at least one Student-held Seat has not; in a Guided Week opening the Week counts as ordering. Waits count from `wait_started_at` on the open turn, the same source Students see.
- Staff never see progress as Weeks played of a total or anything hinting at game length (show share finished and status). Only the staff insight endpoint serves the full chain, demand series and number of Weeks.
- Lecturer test Games and simulation Games never appear in overview, funnel or aggregates (via `games.policy(purpose)` / `reports.scope`).
- Messages are one-way: no reply, reaction or forward, no Student write route. Recipients: one Student; a Class game (every Student ever seated, including where an AI now sits); a Class session (all registered Students); an explicit Student list passed by calling modules (for Epic 13). AI players and unregistered Roster addresses get nothing. Plain-text rendering with line breaks kept, everything else escaped, in product and mail. Max length configurable (placeholder 2 000 chars), stable error code.
- Idempotent send: a client-made key, unique on `messages`, prevents double sends.
- Copy: Norwegian bokmål in `frontend/src/copy/nb.ts` only; draft copy marked for review. No «Beer Game»/«bullwhip» pre-Debrief copy. WCAG 2.1 AA, text ≥ 9 px only inside wall cells, 13 px elsewhere; no page-level horizontal scroll; Playwright + axe at 1440 px, 320 CSS px (1280 px at 400 % zoom, 200 % text) per story; Skjelett in real layout while loading, never a spinner.
- Updates must reach the Oversikt within 5 s; fixed query count for the overview (test with 100 Class games, no per-Game queries).

## Technical Decisions

- `game_summaries` (one row per Game, owned by `modules/games`) is the only source of status for lists; updated in the same transaction by every `games.commands` command (`create`, `assign_seat`, `move_seat`, `start`, `view_week`, `place_order`, `advance`, `switch_to_rule_based`, `finish`). Stores status, current Week, waited-for Seats and since when, four occupants (kind and `user_id`, never names) and running chain Total cost. Migration backfills existing Games; an api test asserts stored row equals fresh recomputation after each command.
- Endpoints, all through `platform/authz` policies/scope helpers, with `ETag` and `If-None-Match` → `304`: `GET /api/class-sessions/{id}/overview` (summary list envelope, headline counts, `server_now`, longest-waiting game named by the api, median/quartiles of finished chain costs; names resolved at read time); `GET /api/games/{id}/weeks` (ETag tied to Game `version`; integers for units, decimal strings for money); `GET /api/class-sessions/{id}/overview/aggregates?role=&cells=&status=` (one filter combination at a time, no aggregates in the overview response); the Spillinnsikt insight endpoint; Messages send/list endpoints.
- `analysis.wall_aggregates` (pure, in `backend/app/analysis/`, reusable by the Class report) takes stored Week states and returns per Uke the median row, average chain cost row and number of Games counted, over Games that have reached that Uke; golden tests for odd, even, single and zero Games. A pure `analysis` function also supplies cost median and quartiles. The decision is recorded against the spine's Deferred item «Wall filter aggregates».
- Web app is presentation only (AD-10): it groups, sorts and filters rows it received, computes no quantity, median, average or cost, and refetches week data only for Games whose `version` changed.
- Live updates reuse Epic 6's SSE: `session:<id>` and `game:<id>` events invalidate TanStack queries via the mapping in `frontend/src/lib/api/topics.ts` (the only topic→query-key map); `user:<id>` refetches Student Messages. Session events coalesce to 1 per 2 s. Wait durations tick from `server_now`; refetch at `next_change_at`; browser clock never decides status.
- `progress.service.funnel(class_session_id, student_ids)`: counts step events for given Students, cached per Class session, invalidated by `progress.record_step` (which also emits `session:<id>`); `progress` imports no feature module; takes no AI score or text; steps nobody records yet show 0.
- Single AD-15 mapping of `decided_by`/`fallback`/`occupant_kind`/`reason` to display marks lives in `games` `service.py` (Story 6.14 added it with `guard_switch`); extend it, never add a second one; test every `reason` and `fallback` value including Epic 8's Takeover reasons. Insight links come from providers registered via `register_insight_links(provider)` (same pattern as pin providers of Story 5.11); none registered in this epic, so `modules/games` imports no later module.
- `messaging.service.send_message`: one transaction stores one `messages` row and one `message_recipients` row per Student (text, Class session, `user_id`s, times; no copied names or emails), calls `platform/notify.enqueue(user_id, kind="message", dedupe_key, ref)` per recipient, emits `session:<id>`. Kind `message` registered `immediate` in Story 3.5's delivery table; mail is a Jinja2 Norwegian template in `backend/app/platform/email/templates/`, headed «ØL-spillet», with the text and a link to Hjem; local dev uses the mock mailer.
- Charts (hand-made SVG, fixed width passed in, `<title>` on every SVG, no `ResponsiveContainer`) go in the shared `frontend/src/components/charts`: Matrisevegg (Role as prop, `net-neg-*`/`net-zero`/`net-pos-*` and `flow-*` bins, square corners), class median graph, Kostnadsfordeling (ticks, box, labelled median), Ordrestolper and Rolle × Uke table (prop for the viewer's own Role, unset for staff; reused unchanged by Epic 9). Record in the chart README whether the wall is exposed as SVG table roles or an HTML table underneath (founder decision 2026-11-14: wall is never `aria-hidden`).
- Money formatting only via the existing single Norwegian number formatter (true minus, narrow-cell option); money as decimal strings.

## UX & Interaction Patterns

- Oversikt: headline counts, «Oppdatert hh:mm:ss» caption, games grouped Venter, Pågår, «Ferdig, lavest kjedekost øverst» (headers with counts); each row: «Spill n», Uke number, whom it waits for (name, Role, duration), four Seats (name or «KI-spiller»), kjedekost. Before the Start date the wall is empty and shows allocation without costs; unstarted games after it get their own group. Below 1024 px one column; right rail («Venter ellers», «Klassens kostnad» with per-Role average bars, «Trakt» funnel with `aria-hidden` bars and list-item counts) stacks under the wall.
- Matrisevegg: one row per game, one column per Uke, sticky game column and Uke header inside one scroll region (`role="region"`, name «Alle spill», `tabindex="0"`). Cells print signed number if it fits with 1 px to spare, otherwise only «−» for below zero, else blank; text `ink` on steps 1–2, `paper` on 3–4; always-visible legend with bins and the line «− i en celle: restordre (under null).» One Tab stop; arrows move cell by cell, Home/End to row ends; focus ring `focus-ring-inset`; cell accessible name like «Spill 2, Uke 14: Netto lager −13.»; focus kept by Game id and Uke across re-renders.
- Visningsbryter «Vegg» / «Vis som tabell» (built from Epic 5's Valgknapper; active segment `ink` with `paper` text); table has signed number in every cell at ≥ 13 px, sortable headers with `aria-sort` (cost sorting on this staff surface only). Veggfiltre (Rolle, Celler, Status with counts) are text-button toggles with `aria-pressed`, active weight 600 and underlined, no pills; filter changes keep previous rows until new ones arrive, failure shows inline error without clearing the wall.
- «Oppdater automatisk» Bryter (Epic 5) on by default at top right of the wall; off freezes wall, table, rail and counts, showing «N endringer siden hh:mm» with secondary «Oppdater». With focus inside wall/table, values update in place but rows never move or re-sort and focus never moves. Headline counts and Varselbånd announced politely at most once per minute. Connection loss after 15 s no event/heartbeat: Tilkoblingslinje, last values kept, nothing greyed out; «Tilkoblet igjen.» for 5 s on reconnect.
- Varselbånd: full-width `restordre-fill` band, `ink` text, «Spill 2 venter på Noah (Grossist) i 23 t.», primary «Send Melding» preset to the waited-for Student; absent when nothing waits (no primary button in its place); the band's game is tinted in the wall, left out of «Venter ellers»; text first, action wraps full width at narrow widths; timestamps never `ink-muted`/`restordre`. Every row has a «Melding» link.
- Spillinnsikt: header with game number, status, four Seats in chain direction (upstream left); per-Role tables (Detaljist to Fabrikk) scrolling in their own regions with sticky labels; per Week and Seat: incoming order, incoming delivery, inventory, backlog, Order, cost, plus text marks for AI-played Weeks, Takeover, guard/cost-limit switch, fallback Order (never colour alone); empty link slot per Student Seat; unstarted game shows «Spillet har ikke startet.»; running game refetches on `game:<id>`; Back returns to Oversikt focused on the same game. Charts for all four Roles plus customer demand, Fabrikk at top, each with «Vis som tabell»; Ordrestolper uses `order-history` bars, first Order ≥ 10 marked with dot and «Uke n» joined by a diagonal, `flow-*` steps for the table, Forsterkning slot shown only when supplied.
- Meldingsskjema: its own page, recipient as title («Melding til Noah, Spill 2»), multi-line Tekstfelt, primary «Send Melding» (`aria-disabled` when empty, keeps focus), no reply field, no free recipients; success line «Meldingen er sendt til 4 studenter.» replaces form and takes focus, plus «Sendt tidligere: 3»; failure «Det ble ikke lagret. Prøv igjen.» inline with `role="alert"`, text kept. Entry points: Oversikt header link (label must not be confusable with the Varselbånd's), Spillinnsikt «Melding», Student link beside a Seat; opens from Epics 8, 13, 14 with a preset recipient. Student Hjem lists Messages newest first (sender, Europe/Oslo time, full text), appearing live, announced politely without moving focus; staff get a «Meldinger» list of sent Messages.
- Landing (Epic 3) gets «Alle spillene på én skjerm»: the shared Matrisevegg fed with bundled static data, labelled «Demodata», no names, week counts or real session data.
