- (decision) Paradigm: modular monolith with a functional core (pure engine + analysis) and imperative shell (FastAPI api + procrastinate worker share one codebase). Prevents game rules leaking into routes/jobs/frontend.
- (decision) Single write path for game state: games.commands (place_order, open_week, takeover, reclaim, pause, resume, playout) each one DB transaction with SELECT FOR UPDATE on the game row; unique (game_id, week, seat). Humans, AI jobs and sweepers all call the same commands. Prevents double week-advance and divergent takeover logic.
- (decision) Seat view projection is the only source for what a Seat sees: same function feeds the student API response and the AI player prompt (FR-31, FR-14, FR-83). Prevents hidden info leaking and AI/human information mismatch.
- (decision) Realtime: push invalidates, pull reads. Postgres NOTIFY in the mutating transaction, one LISTEN connection per api process, FastAPI native SSE stream per user, frontend invalidates TanStack Query keys and refetches via REST. Events carry ids+version only. Rejected: WebSocket (bidirectional not needed), Redis pub/sub (extra service), polling-only (NFR-1 2 s).
- (decision) Jobs: procrastinate on Postgres (no Redis). Timers are data: deadlines and limits stored as columns; a periodic sweeper (every minute) performs due actions idempotently via games.commands. Queues: ai-orders, llm-batch, reports, mail. Rejected: Redis+arq (extra service), many one-off scheduled jobs (lost-job risk).
- (decision) AI gateway: app/ai is the only importer of pydantic-ai and provider SDKs. Every LLM call carries purpose + class_session_id + prompt_version; gateway resolves pinned model config (FR-68), budget check with reservation (FR-69), PII scrub of free text against the roster (PRD 6.1), timeout/retry per Effort level (FR-32), schema validation, llm_call log row (FR-67). Mock provider when no key.
